# 有界搜索的目录索引修复

修改原因：eTech 改用 `/api/v2.1/cloudfile/search/` 有界索引查询后，旧 Meili 索引器仍只消费 `obj_type=file` 的 Activity 行。目录没有候选文档，前端无法展示目录；这不是前端过滤导致的。原生降级查询虽然支持文件/目录，但只查当前层，不能把降级当作完整全库搜索。

## 修改与验证

目录 `dir/folder` 的创建、批量创建、恢复、移动、重命名和删除进入原有增量索引链。目录只索引名称、路径和标签，不读取文件内容或文件大小；目录类型为 `object_type=dir`，目录范围过滤保留祖先路径。查询仍实时检查存在性、库范围、父目录及目标权限；索引不能授权访问。前端保留文件和目录，EAP 兼容 `folder/dir` 并对目录自身执行权限裁剪，不生成文件预览地址。

目录标签读取兼容现有目录 UUID 的旧标签绑定，不能复用强制 `is_dir=False` 的文件标签查询。目录标签读取失败时不推进修复检查点，避免误将未收录标签的目录标记为完成；普通文件标签逻辑保持不变。

历史目录不会因升级自动出现在索引中，需要一次补索引。新增以下显式运维命令，不在用户请求中扫描目录，不启动额外定时任务。

```sh
python manage.py cf_search_backfill_directories \
  --repo-id <资料库UUID> \
  --checkpoint /持久化运维目录/search-directory-cursor.json \
  --max-pages 10
```

先部署包含修复的 Hub/worker，并确认已有 Meilisearch provider 及索引配置。相同命令逐批重复运行，输出 `complete=True` 才表示该库全部目录补入完成。每次默认最多10页、每页100个直接子项；空目录也进入索引，只为目录构建文档，不更新普通文件内容。检查点只保存库、固定提交、待处理路径/偏移和进度，权限0600；同一检查点加独占锁，不能多个运维进程并行推进。命令复用服务端 Meili 配置，不在命令参数、前端或检查点暴露凭据。

分页读取固定提交；库 head 变化时拒绝继续，需在库内容稳定时从新的检查点重跑。文档写入等待 Meili task 成功后才推进检查点，失败/超时保持原位置，重试稳定ID幂等覆盖。命令不删除已有索引；旧目录路径的候选会被实时存在性检查排除。大目录迁移若只产生父目录事件，后代新路径仍需按本命令补齐，不在一个增量事件中递归扫描。补索引结果在完成前逐批可见，不宣称原子全量发布。

本地回归覆盖目录文档不读字节、增量创建/改名/删除、有界宽目录续页、空目录和多级目录、命令恢复、异步任务失败不推进、目录/文件混合命中与撤权裁剪。生产验收应选一个既有空目录、一个含文件目录及同名文件，在“全库 / 所在目录”分别搜索，并核对未授权目录不出现。代码测试不等于生产补索引已完成。
