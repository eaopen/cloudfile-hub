# 分享安全审计与最小修复（2026-11-13）

## 结论与范围

本轮交付关闭状态下的最小安全修复，不开放 Etech 分享入口或匿名外链。代码级审计结论为 **不具备开放条件**。原生 `CF_ENABLE_SHARE_RESTRICT=True` 默认不变；既有配置未修改、未部署。配置被显式改为 False 的现网不在本次源码修复中自动收敛。

不新增分享表、身份层、逐文件 ACL、全库扫描、缓存或后台任务。`FileShare` / `UploadLinkShare`、CE 角色与所有者校验继续有效。内部 Smart Link 仍只是地址，访问走实时身份及目录权限。

## 已确认缺口与本次修复

| 缺口 | 修复 | 验证 |
| --- | --- | --- |
| Etech UI 隐藏但创建/修改 API 可直接调用；rw 被当成分享权 | 创建与修改明确返回 403；删除批量循环及密码回显；列举/撤销使用既有库管理权 | Java 定向测试 |
| EAP 只检查 URL 库根写权限，未绑定 token 实际库 | 读取当前用户的 owner-only 详情，校验 repo_id/token/path；CE 删除再次验证所有权 | 跨库拒绝、无管理权不出站、正常撤销测试 |
| 原生详情可凭他人 token 读取路径/可恢复密码 | 下载和上传链接详情都只允许创建者；返回 password=null、has_password 布尔值 | 正反所有者及序列化测试 |
| 原生旧版按库删除仅验证 URL 库 owner | 原生旧版与 v2.1 下载/上传链接删除查询均绑定 token+repo_id；修正旧上传接口错误异常类型 | 4 个入口的跨库/正常撤销测试 |
| 限制开关在创建、页面、上传、缩略图/内部回调等入口不一致 | 复用一个现有开关检查，接入原生模型创建和有效 token 解析、页面装饰器、密码/范围验证，以及绕开这些共用点的消费入口 | 22 个函数的关闭态执行测试、页面包装器测试；不是数据库/HTTP 集成测试 |
| 密码通过响应回传、更新 URL query 泄露 | Hub 用户详情/列表不解密回传；EAP DTO 忽略历史 password 字段；更新改 JSON body；隐藏前端只保存密码状态 | Hub/Java 序列化、前端请求测试 |
| 用户全局第一页之后才按对象过滤，可能漏掉目标链接 | EAP 按 repo_id/path 请求原生过滤；保留 CE 默认有界首页，不全库遍历 | HTTP query 编码测试 |

关闭限制对 staff 也适用于创建和外链内容消费；不再保留“管理员能创建但链接不可用”的半开状态。所有者详情/列表、原生管理员审计和撤销渠道保留。关闭态不依靠前端按钮，不以扫描后代 ACL 替代授权。

## 未通过/未执行的开放验收

- 未运行真实 Django/Seafile/MariaDB 环境；Hub 测试执行实际函数代码，隔离 CE 导入/数据库/RPC。Python 语法与隔离测试不能等同部署验收。
- 未验证已签发 Server 临时下载/上传票据的缓存与失效时间、已经开始的 Range 请求；本轮未改变 Server。因此不能声称关闭/撤销会立即杀死所有已签发票据或进行中的传输。
- 未运行完整匿名正确/错误密码、到期、撤销、分片、Range、缩略图、盲上传矩阵。开关 False 时保留原生密码校验，仅隔离测试验证正确/错误密码。
- 外链是创建者的独立授权，不能声称匿名目录内容自动与内部每个人的 ACL 求交。目录包含敏感后代时，不允许以本次关闭态修复为开放依据。
- FileShare 持久化 repo_id/path，不能宣称其具有稳定文件版本身份。重命名、移动、删除、同路径重建的旧链接行为必须在真实环境实测；本轮不猜测或改变 CE 路径语义。
- 开关 False 时保存到资料库等原生消费路径的密码/到期/路径范围完整性还需专项验证；本次通过关闭边界避免暴露，不代表开放态完整安全认证。

## 与文件保护开发隔离

对照 Hub `feat/file-protection-v1`（PR #100）相对 dev 的改动，当前分享补丁文件无交集。未修改 schema、file_protection、rust_edit、directory_page、audit、Server 文件写入/CAS/保护 SQL。现有五表主线不被本任务改动，保护分支的 Schema 扩展由其独立任务负责。

保护状态是写保护而非保密授权；不能推断“受保护文件不可下载”，也不能让匿名上传绕过未来保护终判。合流后仍需验证保护文件只读访问、覆盖/替换/目录移动阻断与旧票据行为。

## 接口兼容与集成

- Etech 新建/修改外链明确返回 403，UI 保持 `shareEnabled=false`。
- Etech PUT 更新参数改 JSON body，旧 query 客户端不再受支持；此接口未开放。保留创建 DTO 的 count 仅作输入兼容，不执行批量创建。
- 原生密码输出变为 null，新增 has_password；EAP 使用 hasPassword。旧客户端不可再依赖密码回显；以后开放原生外链 UI 时需校验其编辑保留密码行为。
- EAP 撤销依赖此 Hub owner-only 详情修复；配套交付，勿将旧 Hub 的 token 详情当作所有者证明。
- EAP/Web PR-B 分支基于各自 PR-A，PR-A 合入前以 PR-A 分支为审阅基线；不合并或部署。
- Docker 仅登记上游补丁文件清单，不修改镜像、Compose、环境变量或启动配置。
